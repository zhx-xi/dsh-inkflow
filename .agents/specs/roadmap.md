**为什么 B0 必须先做「注册表化」**：`writeIndexDatabase()` 的 DDL 是一整块 `db.exec` 模板串（`src/host/indexer.ts` 508–522），INSERT 也在同一函数（524–563）；`scanProject()` 把既有不变量 code（`OUTLINE_*`、`CHARACTER_NAME_DUPLICATE`、`WORLD_ROOT_*`、`DANGLING_PARENT`、`DUPLICATE_ID`）写在同一函数里（约 370–470 行之间）。不先把这三处改成「域模块提供片段、`indexer.ts` 只按注册表执行」，B1/B2 的六个域单会在同一函数里排队，批次内的并行不成立。

**跨单契约（B0 定死，B1/B2 不得改列集）**

| # | 契约 | 说明 |
|---|---|---|
| X-1 | `entities` 是跨类统一投影 | 列集 `kind / id / path / title / name_key / category / parent / order_index / status / keywords / aliases`；**主键 `(kind, id)` 复合**：不同目录是不同表、各有主键，两个 kind 可以合法共用一个 id（I-04 只报 `DUPLICATE_ID`、两行都保留），单列主键会把这种既有合法状态判成不可表示；`name_key`/`aliases` 的归一化**只有一处实现**（`indexer.ts:84 nameKey()` 提到 `domains/naming.ts`，域单与 #29 都调它）；`entities` 与域表的行必须由同一次 scan、同一事务产出，不一致报 `ENTITIES_DRIFT`（I-15） |

**估工口径**

- 总估工 **122–162 人日**：净开发 99–130、缓冲 23–32（【推断】拆分）——这是**承诺值**，不随逐项重估而改动。
