# dsh-inkflow 产品范围（Product Scope）

> **依据**：[ADR-0001](../adrs/0001-single-plugin.md)（单插件）、[ADR-0005](../adrs/0005-files-first-with-derived-index.md)（文件真相）、[ADR-0006](../adrs/0006-workspace-contract-v2.md)（单工作区单项目）、[ADR-0007](../adrs/0007-plugin-shared-library.md)（共享库）、[ADR-0008](../adrs/0008-panel-data-channel.md)（面板通道）、[ADR-0009](../adrs/0009-ovk-semantic-search.md)（语义检索）。
> **依赖**：[conventions.md](conventions.md)（契约）、[data-model.md](data-model.md)（数据形状）、[roadmap.md](roadmap.md)（阶段/波次/估工）。
> **相关 ADR**：0001–0009（差异点③与共享库分别由 0009 / 0007 支撑）。
> **状态**：活跃。已裁决口径见 [open-questions.md](open-questions.md) §2；未裁决项见其 §1。

> **一句话定位**：一个 DSH 插件（Host + Client 双半）在本地单机完成长篇小说的全部创作流程——**作品是用户自己 git 仓库里的 Markdown/JSON 文件，SQLite 只是可删可重建的派生索引**；复用 DSH 的 agent/skills/模型配置，不做 Chat UI、不自研编排。
> 三个差异点：①旧稿/设定 → 结构化资料库的**提取管线**；②**系列共享设定 / 同世界观多故事**（插件级共享库 + 复制快照）；③**复用 OpenViking 的语义检索**（不自研 embedding / 向量库）。

## 1. 定位与产品形态

### 1.1 产品定义

| 维度 | 内容 | 来源 |
| --- | --- | --- |
| 是什么 | 一个 DeepSeek Harness（DSH）插件，目标「一个插件完成长篇小说创作全部功能」 | 【已定】 |
| 为什么是单插件 | 不拆多插件，避免插件冲突与升级兼容问题 | 【已定】 |
| 交付形态 | DSH 插件包（Host 半 + Client 半），不是独立桌面应用、不是 Web 服务 | 【已定】 |
| 技术栈 | 纯 TypeScript，零运行时依赖 | 【已定】 |
| 运行边界 | 第一阶段完全本地单用户；不做账号 / 计费 / 远程服务端，仅在架构上预留同步接口 | 【已定】 |
| 作品存放 | 用户自己的小说 git 仓库（九个内容目录 + `inkflow.json` + 派生 `index/`） | 【已定】+ [conventions.md](conventions.md) §2 |
| 插件数据 | `$DSH_HOME/inkflow/`：`state.json`（仅展示用状态）+ `shared/`（插件级共享库） | 【已定】+ [ADR-0007](../adrs/0007-plugin-shared-library.md) C1 |
| 持久化 | 作品 = 文件；索引 = `node:sqlite`（`index/inkflow.db`，可删可重建） | 【已定】 |
| 许可 / 可见性 | 仓库 public、MIT | 【已定】 |
| 迁移节奏 | 旧 InkFlow 库（43 表 / 59 万字）迁移不在第一阶段，排在 0.5.0 波次 | 【已定】 |

### 1.2 DSH 插件双半形态

| 半 | 运行位置 | 职责 | 来源 |
| --- | --- | --- | --- |
| Host 半 | Node 进程内 | 工具注册、私有内部通道、skills provider、写作 preset、索引与文件 IO | 【已定】 |
| Client 半 | React | 在会话视图（`conversation.view`）注册「这本书的驾驶舱」 | 【已定】+ [ADR-0008](../adrs/0008-panel-data-channel.md) D1 |

### 1.3 复用与自制边界（本项目最大的架构约束）

| 事项 | 复用 DSH | 自研 | 来源 |
| --- | --- | --- | --- |
| 会话 / 聊天界面 | 是（DSH 原生 chat） | 否 | 【已定】 |
| agent 循环 / 编排 | 是（DSH 自带 agent） | 否 | 【已定】 |
| 技能（skills） | 是（复用 DSH skills 机制，本项目提供 5 个**写作工艺** skill） | 部分：skill 内容 | 【已定】 |
| 记忆 / 日志 / 模型配置 | 是 | 否 | 【已定】 |
| 语义检索 | 是（OpenViking） | 否（不引入 embedding/向量库） | 【已定】+ [ADR-0009](../adrs/0009-ovk-semantic-search.md) P1 |
| 工具注册 | — | 是：约 20–30 个 `inkflow_*` 工具 | 【已定】 |
| 面板数据通道 | — | 是：`/inkflow/internal/*` 私有内部通道（不是 API） | 【已定】+ [ADR-0008](../adrs/0008-panel-data-channel.md) D2 |
| systemPrompt 注入 | — | 是（注入写作简报/上下文） | 【已定】 |
| 后台任务 | — | 是（提取管线、批量写作、久任务） | 【已定】 |
| 数据持久化 | — | 是（文件 IO + `node:sqlite` 派生索引） | 【已定】 |
| 页面宿主 | — | 是（React 视图，**禁止 iframe**） | 【已定】 |

**不做「操作 skills」**：工具怎么用写在工具描述与 spec 里，不再额外发一套教 agent 调用 `inkflow_*` 的技能包。

### 1.4 硬性技术禁忌

| 禁忌 | 后果 | 来源 |
| --- | --- | --- |
| 不嵌 iframe | 违反 DSH 插件形态，无法过评审 | 【已定】 |
| 不自研 Chat UI | 与 DSH chat 重复，且违反「复用」边界 | 【已定】 |
| 不自研 agent 循环 | 与 DSH agent 重复 | 【已定】 |
| 不塞 Python 后端 / sidecar | 破坏纯 TS 与单插件交付形态 | 【已定】 |
| 不做对外 HTTP API、不做 MCP 双通道 | 没有第二个消费者；对外契约只会腐化成负担（[ADR-0008](../adrs/0008-panel-data-channel.md)） | 【已定】 |

## 2. 目标用户

| 用户类型 | 规模假设 | 典型场景 | 核心诉求 | 对应功能 | 来源 |
| --- | --- | --- | --- | --- | --- |
| 长篇小说作者（连载/完本） | 1 人 N 个工作区，每个工作区 1 本 | 每天写 1–3 章、维护庞大设定 | 设定不崩、伏笔不漏、章节可批量产出 | P0 全部 + P1 账本/门禁/简报 | 【推断】 |
| 已有旧稿/旧设定库的作者（旧 InkFlow 用户） | 1 人，旧库含 43 表 / 约 2900 实体 / 59 万字 | 把旧库搬进新插件，继续写 | 不丢数据、不重录、可追溯 | P1 提取管线 + P2 ETL | 【推断】 |
| 系列 / 同世界观多故事作者 | 1 人，2–5 本共享世界观 | 一部作品衍生多部，设定只维护一份 | 共享库取用、副本可溯源、书能独立 clone | P2 共享库 + 同世界观取用 | 【推断】 |
| 技术型 DSH 用户 | 习惯用工具与 agent 自动化 | 用 `inkflow_*` 工具让 agent 批量操作 | 能力可编程、可审计、结果落文件 | P0 工具面 + 派生索引 | 【推断】 |
