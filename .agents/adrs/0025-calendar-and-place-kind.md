# ADR-0025：历法与地点——一个换算函数、一个既有 kind

- 状态：已采纳（2026-10-25）
- 日期：2026-10-25
- 相关：[ADR-0006](0006-workspace-contract-v2.md)（派生物与删库重建）、[ADR-0019](0019-one-level-nested-frontmatter.md)（一层嵌套，解释 `worldTime` 为何仍是标量）、roadmap §2.4 的 X-28、[data-model](../specs/data-model.md) §2/§3.4

## 背景

0.5.0 的 #48（多纪元双轴 + 知识图谱 + 地图）踩在两条既有口径上，两条都不是新问题：

| 口径 | 现状 | 如果不先定 |
|---|---|---|
| 时间 | `timeline/*.md` 的 `worldTime` 是扁平标量 `YYYY[-MM[-DD]]`（[data-model](../specs/data-model.md) §3.4），排序只能靠字符串比较 | #48 要多纪元（纪元偏移 + 闰规则）。同一串 `0500-03-01` 在两个纪元是两个日子；换算散落在索引、面板、简报三处之后，差一天没有任何地方会报错——它只会让一个期限每次重算时悄悄移动 |
| 地点 | 地点从 0.2.0 起就是 `world/<category>` 的分类（X-7），**不是**独立 kind | 地图若为地点新开目录或新 kind，等于给同一批条目两个身份：改名（ADR-0014 的 id 钉住）、影响面、提及扫描、检索全都要各认一套 |

## 决策

### D1 一个纯函数：`src/host/calendar.ts` 是历法解释的唯一实现

- `toAbsolute({era, y, m, d})` ⇄ `fromAbsolute(days)`，外加 `calendarDaysBetween`、`monthLength`、`isLeapYear`、`eraAt`、`findEra`、`validateCalendarSpec`。
- 历法**可配置**：`CalendarSpec` = 若干个 `EraSpec`（`{ id, label, epochOffsetDays, months[], leap: none | { every: N, month, days } | 'gregorian' }`）。默认表是单纪元格里历（day 0 = `0001-01-01`，`1970-01-01` = 719162）。
- 零依赖、无 IO、不碰 `Date`：同一个纯函数才能被用例逐日跑到「零误差」，而 `Date` 把时区与本地日历拖进来，性质就验不动了。
- **永不抛**：所有入口返回 `{ ok: true, value }` / `{ ok: false, error: { code, detail } }`。`CALENDAR_*` 是函数参数拒绝码，和 `io.ts` 的 `PATH_*` 同类，不属 data-model §5 的数据不变量目录——它描述的是「你给的参数不成立」，不是「书里的内容违反了不变量」。

### D2 `A→B→A` 误差 0 是硬性质，不是容差

`toAbsolute(fromAbsolute(n)) === n` 必须对**每个整数日**成立，含闰日、世纪规则与跨纪元边界。因此：

1. **不用平均年长度估算**：`fromAbsolute` 先用「每至少 `base` 天」把上界夹住再二分，而不是 `365.2425` 乘除——平均值在闰日旁边必然差一天，而差一天的性质是「偶发」，最难查。
2. **闰日三档都要有用例**：`2024`/`2000` 的 2 月是 29 天、`1900`/`2100` 是 28 天；平年写 `2/29` 被拒，而不是就近取 `2/28`。
3. **纪元边界有明确归属**：`day −1` 属更早的纪元、`day 0` 属本纪元；纪元前的日期用**更早的纪元**表达，不用 `y = 0`（`y < 1` 直接拒）。
4. **拒绝而不是猜**：未知纪元、月 `0`/`13`、该月没有这一天、非整数、`NaN`/`Infinity`/字符串、历法表本身非法（空 `eras`、重名、纪元乱序、月长 ≤ 0、`every: 0`、闰月越界、未知闰规则）全部结构化拒绝，且**表在换算前就被 `validateCalendarSpec` 拒掉**。

### D3 文件保持标量，绝对日只是派生列

- `timeline/*.md` 的 `worldTime` **不改形状**（仍是 `YYYY[-MM[-DD]]` 标量字符串）：文件是真相，解释权在 D1 这一个函数。改成嵌套对象会让 0.3.0 定的读回约束（ADR-0019）与既有全部时间线文件一起作废，收益只是「字段看起来整齐」。
- #48 在**索引**里加派生的绝对日列，并 `INDEX_SCHEMA_VERSION` +1。按现有口径（索引是缓存、不写 `ALTER`）这意味着升级后删库重建一次，代价可控。
- 派生列**不进任何内容文件**，也不回写 frontmatter：一旦回写，就成了「同一事实两处存储」，7 天之内必漂（这条与版本号那次是同一个教训）。

### D4 地点不新增 kind

- 地点就是 `world/<category>` 的条目，地图**只挂既有条目**；`kind` 集合不变，`entities` 投影的 `(kind, id)` 主键不变（X-1）。
- 地图页的跳转按 `(kind, id)` 解析（世界书条目已有 id），不新开一个「地点表」。
- 坐标这类**展示用**信息若确实需要，落在世界书条目的 body 或 `extra` 里，由地图页读取；不新建 `locations/` 目录——新增内容目录要动 `CONTENT_DIRS`、九项 `.gitkeep`、门禁四态与全部迁移路径，代价与收益完全不成比例。

## 备选与取舍

| 方案 | 优点 | 代价 | 为什么没选 |
|---|---|---|---|
| 各面板与索引各算一遍换算 | 少一个模块，写起来最快 | 两处实现对闰日的理解一有差异就差一天，且差在谁身上看不出来 | 纯函数才能被「逐日往返 0 误差」这条用例盯住；这是本项目唯一能自动验证时间正确性的办法 |
| 用平均年长度（365.2425）估算 `fromAbsolute` | O(1)，代码短 | 闰日旁边必差一天，且偶发 | 先夹上界再二分是 O(log 年数)，与一次文件解析比可忽略 |
| `worldTime` 改成 `{ era, y, m, d }` 嵌套对象 | 字段自解释 | 作废 0.3.0 的读回约束（ADR-0019）与全部既有时间线文件；解析成本反而更高 | 文件是真相：把纪元写进文件名之外的字段是「多存一份可推导的信息」 |
| 索引里存 ISO 字符串（`0500-03-01T00:00`） | 与现有 `worldTime` 同形，可直接比较 | 跨纪元不可比（字符串大小 ≠ 日子先后），正是本条要解决的问题 | 绝对日是**整数**，比较与差值都是天然可用的；字符串只能比较、不能相减 |
| 地点新开 kind `location`（或新目录 `locations/`） | 地图数据模型更「正」 | 同一批条目两个身份：改名、影响面、提及、检索、外链全要改；还要动 `CONTENT_DIRS` 与门禁 | 地点本来就在世界观里（X-7 已定），地图是**视图**不是数据源 |
| 历法规则写死在代码里，不做可配置表 | 少一层数据结构 | 多纪元是 #48 的验收项（D5-6「换算可逆」），写死等于只支持一种历法 | 可配置表 + 一个默认表的成本是多一个类型，收益是实现与「这个作者的历法」解耦 |

## 后果

| 收益 | 代价与对策 |
|---|---|
| 时间换算只有一个实现，多纪元接上就行 | 纯函数无缓存，每次重算；量级 O(月数 + log 年数)，可忽略 |
| 派生绝对日列让「跨纪元排序/相差几天」变成一次整数比较 | 升级要删库重建一次；索引从来就是可重建的，这与它的契约一致 |
| 地点不新增 kind：地图、改名、影响面、检索共用一套条目 | 地图不能有「只为地图存在」的字段；坐标只能寄生在 body/extra 里，需要约定写法（#48 定，不新增目录） |
| 拒绝而不是猜，错误可定位到具体参数 | 调用方要处理 `{ ok: false }`；这比 try/catch 更显式，也正是本仓既有风格（`io.ts`/`zip.ts` 同形） |

## 验证

- `tests/calendar.test.js`（本单已落地，13 个用例）：`A→B→A` 逐日 0 误差（2019–2029 全量 + 锚点两侧 0–800 天）、闰日三档（2024/2000 = 29，1900/2100 = 28，平年 `2/29` 拒）、双纪元表 `−3652…1600` 逐日往返 + 纪元边界归属 + 新历 `every 4 years` 的闰月、`eraAt` 选择、`calendarDaysBetween` 有符号/跨纪元、非法输入 11 种与非法历法表 10 种一律结构化拒绝、纯函数性（同输入同结果）。运行：`node --test tests/calendar.test.js`。
- #48 落地时追加：索引的绝对日列与 `toAbsolute(worldTime)` 逐条相等；同一项目重建两次得到同一组值（派生列的确定性）。
- #48 地图落地时追加：每个图钉都能解析到既有的 `world/<category>` 条目；`kind` 集合里不出现 `location`（对 `DOMAIN_MODULES` 的 kind 全集断言）。
