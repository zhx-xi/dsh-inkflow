# ADR-0001：一个插件承载全部功能，不自研编排

- 状态：已采纳（用户拍板）
- 日期：2026-10-21

## 背景

DSH 插件市场已有 8–10 个活跃的小说创作插件（Openwrite 845★、novel-forge、novel-studio、AI-Novel-Writer 1655★ 等）。按功能拆分意味着用户要装多个插件：插件之间争抢槽位、互不兼容的数据模型、各自独立的升级路径——用户明确把这条列为要避免的痛点。

同时，DSH 已自带 agent 循环、chat、skills、memory、模型与凭据、审批、日志。自研这些等于在别人的宿主里重造一套更差的。

## 决策

1. **单一 bundle**：`dsh-inkflow` 一个包同时提供 Host 半与 Client 半，覆盖 P0–P2 全部功能面；不拆 `dsh-inkflow-core` / `-ui` / `-extract` 之类的多包。
2. **复用 DSH 而非重造**：写作流程用 `agent preset + SKILL.md`；对话与续写用 DSH Chat；模型与凭据用 DSH 的 provider 体系；不实现 agent 循环、不做 Chat UI。
3. **插件只负责小说领域**：数据模型、确定性算法（字数/风格/一致性/历法）、工具面、工作台 UI、提取管线。

## 后果

- 升级只有一个入口；用户只需信任一个包。
- 单包体积会变大（P2 预估 UI 与 skills 占大头），构建产物需按 `files` 白名单收敛。
- 所有功能共享一套数据模型，跨功能（如大纲↔章节↔伏笔）联动成本低。
- 风险集中：一个回归影响全部功能 → 用版本化迁移 + 契约测试兜底。

## 验证

P0 已验证：单包的双半（Host 工具 + Client 槽位）可同时装载并被 DSH 识别。多插件拆分方案不再评估。
