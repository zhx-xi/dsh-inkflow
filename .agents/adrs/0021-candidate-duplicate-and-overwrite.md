# ADR-0021：候选遇到既有实体的三种结局（跳过 / 询问覆盖 / 硬冲突）

- 状态：已采纳
- 日期：2026-10-25
- 相关：ADR-0017（提取由会话模型产出、插件只做队列与落地）、DR-0012（`.inkflow/` 私有状态）、roadmap X-17（批量写＝预览＋备份包＋回滚）、data-model §22

## 背景

ADR-0017 D4/D5 定下的规矩是「采纳**从不覆盖**既有实体」：候选只能创建新文件，撞上已存在的东西就报该域自己的码（`CHARACTER_NAME_DUPLICATE` / `DUPLICATE_ID` / …）并零写盘。0.4.0 的验收（`D:/tmp/inkflow-040-verify-result.md` §二）暴露了这条规矩的实际后果：

- 同一章被**第二次**提取时，同一个角色会再次变成候选，采纳时以 `CHARACTER_NAME_DUPLICATE` 失败；
- 作者事先无法知道哪几条必败，点到才发现，且**内容其实一模一样**——本该什么都不用做。

作者随后给出新的口径（原话要点）：**第二次采集到 id/标题相同的东西时，比较内部内容；一致就直接跳过；不一致才显示，并在 UI 上说明「已存在，但内容不一致，是否覆盖」**。也就是说：

- 「同一实体、同样内容」不是冲突，是**无事可做**；
- 「同一实体、不同内容」不是错误，是**要不要替换**的决策，属于作者；
- 只有「同一身份被**另一个东西**占着」（跨类同名 id、域不变量拒绝）才仍是**硬冲突**。

## 决策

1. **一个判定，三种结局。** `judgeCandidate()`（`src/host/extract-accept.ts`）返回：
   - 无 `existing` → 普通创建；
   - `existing.state = 'identical'` → 书里已经是这句话，**跳过**；
   - `existing.state = 'different'` → 同身份、异内容，**问作者**；
   - `{ ok: false }` → 硬冲突（跨类 id、`FRONTMATTER_ISSUE`、域 `validate()` 拒绝）。
   `propose` 与 `accept` 调**同一个**函数：提交时用它决定「丢掉还是标记」，采纳时用它决定「写入还是拒绝」。第二个判定会在某个域加不变量时立刻漂。

2. **「内容一致」按读者意义比，不按字节比**（`src/host/extract-compare.ts`）：
   只比**候选自己提供的字段**（没提的字段不能算「不同」，否则每次重抽都像新东西）；忽略 `id` 与文件簿记键（`updatedAt`/`rev`/…，角色卡的 id 是随机 uuid）；正文按 CRLF→LF、行尾空白、首尾空行归一；列表按集合比（`keywords`/`aliases` 顺序变化不算改内容）。答案带上**哪些字段不同**，因为「不一致」三个字对作者毫无用处。

3. **一致 → 不建候选。** `propose` 直接丢掉并在回答里列 `skipped`（`label` + 已存在的路径）。候选队列只放「需要作者决定的东西」；这个跳过**不写任何内容目录文件**，因此重抽是幂等的（重复调用不会长出重复候选）。

4. **不一致 → 建候选，但带 `duplicate` 标记，且采纳需要显式 `overwrite`。**
   标记形如 `{ state:'different', path, digest, changedFields[] }`，是可选的（无冲突不写，旧候选文件逐字节兼容）。`accept` 在没有 `overwrite: true` 时以 `OVERWRITE_REQUIRED` 拒绝并说明差异字段；带了才替换，并且：
   - **先开 `replace` 备份包并 stage 旧字节**（X-17：批量写＝预览＋备份＋回滚），包内留 `change: 'modified'` + `before` 摘要；
   - **CAS 基线是「propose 时记录的 digest」**，不是采纳瞬间重新测的（否则作者在决定之后手改的内容会被无声覆盖）——不一致回 `FILE_CHANGED` 且不写盘。

5. **面板：覆盖是逐条决定，批量永不覆盖。** 行内显示「已存在，内容不一致（body, title）—— 是否覆盖？」与 `覆盖`（两段式）按钮；`actionableIds` 把这类行排除在批量之外，批量栏另报「已跳过 N 条会覆盖既有内容的候选」。批量勾选里出现覆盖，等于一次误点能重写十几个文件。

## 备选与取舍

| 备选 | 为什么不选 |
|---|---|
| 保持「从不覆盖」（ADR-0017 原样） | 作者的重复提取场景是常态：同一个人被两个方向的提示词各抽一次，作者要在候选页里手工拒绝一半，而内容本来就一样。这是**把无意义的工作留给用户** |
| 一致/不一致都算冲突，只标注 | 一致的那些仍然是人工噪音；而「标注」在 30 条里等于让作者自己点 30 次「拒绝」 |
| 不一致时**自动覆盖**（不问） | 候选是模型写的，正文/字段可能有损（模型漏抄一段）；静默覆盖作者手写的正文是不可逆的编辑。ADR-0012/0015 的一贯口径是「破坏性动作要显式确认」 |
| 用文件字节比较判「一致」 | 手写卡与渲染出来的候选几乎不可能字节相同（键顺序、未写字段、行尾），结论会是「全部不一致」，等于什么都没做 |
| 覆盖时用「当前文件 digest」做 CAS | 采纳时重新算 digest 永远等于当前文件，作者在两次点击之间的手工修改会被覆盖。基线必须是**决定时刻**的 |

## 验证

- `tests/extract.test.js`：#178 五条用例——①一致 → `created` 为空 + `skipped` 一条 + 零写盘 + 队列里没有候选；②不一致 → `duplicate.changedFields` 精确到字段、`accept` 无 `overwrite` 回 `OVERWRITE_REQUIRED` 且文件逐字节不变、带 `overwrite` 才替换且 `.inkflow/backup/<stamp>/files/<path>` 里存着旧字节；③决定之后手改文件 → `FILE_CHANGED`，改动保留；④旧候选文件（无 `duplicate`/`willFail`）仍可读；⑤`world` kind 走同一条判定（不是角色特例）。
- 面板模型用例：`actionableIds` / `duplicateIds` / `skippedIds` / `duplicateLabel` / `toggleAll`。
- `pnpm run check`：1004 tests 全绿，链接/文档/模块表/工具名/guards/package/分支保护全过。
