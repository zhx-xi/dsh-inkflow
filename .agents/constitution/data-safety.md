# 数据安全政策（Data Safety）

> 本项目的用户数据是**长篇小说正文与设定**——丢了无法重写、泄了不可挽回。以下为强制性政策。

## 1. 数据边界

| 数据 | 位置 | 规则 |
|---|---|---|
| 作品（正文/人物/世界观/大纲/资料） | 用户自己的小说 git 仓库 | 插件只读写用户指定/检测到的项目目录 |
| 派生索引 | `<project>/index/inkflow.db` | 可删可重建；不得写入任何只存在于索引里的信息 |
| 插件自身状态 | `$DSH_HOME/inkflow/state.json` | 只放 `lastProjectRoot` 一类机器状态，不放作品内容 |
| 会话日志 | DSH 会话 | 不写正文全文；需要上下文时写摘要或路径 |

**铁律：真相只在作品仓库的文件里。** 任何「只写进索引/缓存」的设计都是数据丢失隐患。

## 2. 写入纪律

**单一写入口**：所有项目文件写入都经过 `src/host/io.ts`（路径解析 + 原子替换 + 写锁）。业务代码不得自行拼路径、不得直接 `fs.writeFileSync` 写项目文件——插件无沙箱（[hard-constraints](hard-constraints.md) H7），一处手写路径就是一个任意文件写原语。

1. **原子替换**：写文件走「同目录 `<file>.tmp-<pid>-<rand>` → `fsync` → `rename` 覆盖」，禁止原地截断写入（崩溃会留下半截正文）。
2. **失败不落半截（可检验）**：写失败时①目标文件字节不变（sha256 不变）②临时文件被删除（目录里不残留 `*.tmp-<pid>-<rand>`）③写锁释放④返回结构化错误（附 `code`、`errno`、`tempFile`）。禁止「先删后写」或「先截断再补」。
3. **崩溃残留可清扫**：持有者已死（pid 不存在）或存在超过 10 分钟的 `*.tmp-<pid>-<rand>`，由下一次持锁写入清扫；清扫只在项目根内、且只在持锁期间进行。
4. **不静默覆盖**：改写既有正文必须走「提案 → 用户确认」（提案制）；提案制尚未落地，当前不提供任何写正文工具。
5. **删除交给 git**：不物理删除正文；删除 = `git rm`（可 `git revert`）。
6. **编码固定**：UTF-8；**新文件**无 BOM、LF 行尾，写入口负责剥 BOM、把 `CRLF`/`CR` 归一为 LF；**编辑既有文件时保留该文件原有的行尾与 BOM**，否则读者改一个字就会得到整章 diff（[ADR-0016](../adrs/0016-preserve-file-eol-on-edit.md)）。读取用户文件时必须容忍 BOM 与 CRLF（用户会用任意工具编辑）。
7. **幂等**：同一操作重跑不应产生重复数据（重复标题、重复文件、重复索引行）。

### 2.1 单项目写锁

- **一把锁 = 一个项目**：`index/.write.lock`（O_EXCL 创建，内容含 `pid`/`token`/`startedAt`）。同一项目同时只允许一个写者，跨会话、跨进程、跨插件代际。
- **拿不到立即失败**：返回 `PROJECT_BUSY`，不等待、不重试成阻塞——工具调用不能因为另一个会话在写而挂住；调用方重试时再判一次。
- **陈旧锁自愈**：pid 已死、`startedAt` 超过 10 分钟、不可解析超过 10 秒写入宽限、或本进程遗留（不在锁表内）→ 视为陈旧，删除后重试一次。没有自愈机制，一次 kill 就会把整个项目写成只读。
- **释放校验 token**：只删除自己持有的锁。锁在进程内可重入（嵌套写复用同一把锁，最外层释放才删文件），避免「写章节 + 重建目录清单」这类多文件操作自杀式抢锁。
- **与索引重建锁分开**：`index/.lock` 属索引重建（派生数据库），`index/.write.lock` 属数据文件；两者语义不同（重建锁把本进程 pid 当陈旧），不复用。

## 3. 危险操作（必须先征求确认）

- 删除/覆盖/批量重写文件；
- 对整个项目目录做迁移、重命名、批量改名；
- 清理 `index/` 之外的任何目录内容；
- 修改用户的 git 状态（commit / reset / checkout）；
- 修改宿主配置（profile、`cordis.patch.yml`、环境变量）。

确认方式：先用只读盘点列出**精确影响清单**（路径 + 数量 + 是否可恢复），拿到「执行」再动手；执行后逐项复核并如实报告偏差。

## 4. 路径与来源安全

- **项目根校验**：写入前必须确认目标是「git 仓库 + 约定目录 + `inkflow.json`」的项目根（目录清单见 [S-03 §1](../specs/conventions.md)）；不接受「看起来像」的路径。
- **单一路径解析**：写目标一律经 `resolveWriteTarget(projectRoot, relativePath)`（[S-03 §5](../specs/conventions.md)）：只接受相对路径；只允许九个内容目录 + `index/`；拒绝 `..`、绝对路径、UNC、Windows 保留名、结尾点/空格、超长路径（绝对路径 > 240 字符或单段 > 255）、以及 `realpath` 后逃出项目根的符号链接/junction。拒绝时**零写入**。
- **路径穿越**：所有相对路径拼接后必须校验仍在项目根内（`realpath` 后子树比对）；`resolveWriteTarget` 与门禁共用 `realpathLoose`/`isWithin`，避免两套判定在同一路径上给出相反结论。
- **`projectRoot` / `root` 参数边界**：显式路径必须 `realpath` 后位于**会话工作区子树**内（工作区 = 会话工作目录），判定发生在任何写盘之前；盘符/卷根、家目录本身（及其祖先）、系统与安装目录硬拒，返回结构化 `PATH_OUT_OF_SCOPE` / `PATH_FORBIDDEN`。跨会话状态（`state.json` 的 `lastProjectRoot`）只可用于展示，不得作为解析来源。
- **脚手架再确认**：向导一律两段式——`inkflow_project_plan` 只读列出将创建/补齐的项，`inkflow_project_init` 必须带 `confirm: true` 才落盘，且只补缺失项、不覆盖；已有文件只进 `skipped[]`（[S-03 §6.3](../specs/conventions.md)）。
- **loopback 校验**：面板内部通道 `/inkflow/internal/*` 只服务本机浏览器（见 [hard-constraints.md](hard-constraints.md) H8）；请求只带 `sessionId`，无会话身份时不得猜测项目，返回 `NO_SESSION_CONTEXT`。

## 5. 密钥与隐私

- **密钥永不落盘到作品目录**，永不下发浏览器；只在 Host 侧使用宿主凭据服务。
- 正文/设定**不进日志**：日志只记路径、数量、耗时、错误码；错误消息里若可能包含用户文本，需截断且不外传。
- 分享/诊断包默认剔除自由文本字段。
- 写测试时用临时目录 + 构造数据，不要把真实作品内容写进仓库或测试夹具。

## 6. 可恢复性

| 场景 | 恢复路径 |
|---|---|
| 误改/误删正文 | `git revert` / `git checkout -- <file>` |
| 索引损坏或版本不符 | 删除 `index/inkflow.db`，重建 |
| 插件状态损坏 | 删除 `$DSH_HOME/inkflow/state.json`（只影响「上次打开哪个项目」） |
| 插件本身故障 | 卸载插件不影响作品：作品在独立 git 仓库里 |

**验收判据**：卸载插件并删除所有插件目录后，作品仓库仍可完整读、可 `git checkout` 回任意历史版本。
