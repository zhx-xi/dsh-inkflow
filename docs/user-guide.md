# InkFlow 使用手册

> 面向**使用者**：怎么装、怎么建书、日常怎么用、出问题怎么查。
> 面向开发者的规范在 [`.agents/`](../.agents/)（章程 / spec / ADR），本目录不放规范。

## 1. 这是什么

一个 DeepSeek Harness（DSH）插件：装一个插件，就能在 DSH 里完成长篇小说创作的全部工作——项目/卷/章、大纲、人物、世界观、伏笔、时间线，以及一个内置工作台。

**核心设计：文件就是你的书。** 每部小说是一个独立的 git 仓库，正文和设定都是你能直接打开、直接搜索、直接改的 Markdown/JSON 文件。插件读取这些文件，并维护一个可随时删除重建的索引（`index/inkflow.db`）用来做检索和统计。

因此：

- 插件升级**不会动**你的书，也不需要跑数据库迁移；
- 你可以用任何编辑器改文件，改完让插件重建索引即可；
- 卸载插件不影响作品，作品永远在自己的 git 仓库里。

## 2. 系统要求

| 项 | 要求 |
|---|---|
| DSH | 桌面版 `0.2.1-rc.2` 或更新（插件靠 `engines.dsh` 校验） |
| 系统 | Windows 10/11（macOS/Linux 未验证） |
| Node | 用 DSH 自带的 Node 24；自行构建时需要 Node ≥ 22.12 |

## 3. 安装与卸载

在 DSH 的插件管理器里安装（推荐）：目标填本仓库的绝对路径，安装后**重启 DSH**。

命令行等价方式：

```powershell
pnpm.cmd install
pnpm.cmd run build          # 生成 lib/index.js 与 lib/client.js
dsh plugin --profile desktop add link:D:\develop\projects\dsh-inkflow
```

卸载：插件管理器里移除该 bundle，然后重启 DSH。**作品不会被动**（它们在各自的 git 仓库里）。

> 升级插件后如果行为没变，先确认已重启 DSH——新代码不会热替换正在运行的旧版本。

## 4. 创建一部新书

一部书 = 一个 git 仓库，根目录必须长这样（九个内容目录 + 派生 `index/`，**每个目录里都有一个空的 `.gitkeep`**）：

```
<你的书名>/
├── inkflow.json        # 项目元信息（schemaVersion / title / author）
├── .gitignore          # 至少忽略 index/*.db*
├── chapters/           # 正文
├── characters/         # 角色
├── world/              # 世界观 / 设定库
├── outlines/           # 大纲
├── foreshadowing/      # 伏笔
├── timeline/           # 时间线
├── relations/          # 知识关系
├── facts/              # 事实账本
├── library/            # 资料（参考素材）
└── index/              # 派生索引（可删可重建，只有 .gitkeep 进 git）
```

每个目录里的 `.gitkeep` 不是装饰：git 不跟踪空目录，没有它，`git clone` 之后目录会消失，插件就会把结构齐全的书判成「缺目录」。

**目录名固定、不可改**——插件靠它判断"这是一个 InkFlow 项目"。

三种建法：

**方式一：在左侧栏书库里点「新开书」**（最省事，推荐）

左侧栏的 InkFlow 图标 → 书库 → 「新开书」→ 选一个目录（一个新建的空目录就行）→ 面板把**将要创建什么**列给你看 → 你确认后它建目录树、写 `inkflow.json`、补 `.gitignore`，需要时跑 `git init`（不 commit、不配远端、不改你的 git 身份）。建完这本书直接出现在书单里，接着在左侧工作区点「新会话」就能开工。

**导入已有书走的是同一条路**：选那本已经有内容的书的目录，检查清单里就只剩"缺什么"，它只补缺失项，**已有的正文、设定、`inkflow.json` 一个字节都不会动**。

**方式二：让 DSH 里的 AI 建**

在新目录里打开一个 DSH 会话，说「在这里建一本叫《书名》的小说项目」。AI 会先调 `inkflow_project_plan` 把**将创建什么**列给你看，你同意后它才调 `inkflow_project_init` 落盘（并代跑 `git init`，但不会 commit、不配远端、不改你的 git 身份）。

**方式三：手动建**

建十个目录（各放一个空 `.gitkeep`）、写 `inkflow.json`：

```json
{ "schemaVersion": 1, "title": "书名", "author": "你的笔名" }
```

再 `git init`、`git add .`、`git commit`。

> 插件只在**四态里的 `usable`** 才工作：① 目录是 git 仓库 ② 九个内容目录与 `index/` 齐全且每项带 `.gitkeep` ③ `inkflow.json` 可解析且版本不高于插件。差哪一项，工具会告诉你缺什么、下一步该做什么。

## 5. 日常使用

### 5.1 左侧栏书库 + 会话工作台

入口有两处，各管一件事（[ADR-0010](../.agents/adrs/0010-book-hub-entry.md)）：

| 入口 | 在哪 | 管什么 |
|---|---|---|
| **InkFlow 书库** | 左侧栏的 InkFlow 图标（root 作用域，任何页面都在） | **列书**：所有被 DSH 打开成工作区的小说目录 + 每本的门禁状态 + 「新开书」入口 |
| **InkFlow** | 会话的「对话 / 轨迹」栏（session 作用域） | **干活**：当前会话所在那本书的章节树与编辑器（[ADR-0008](../.agents/adrs/0008-panel-data-channel.md)） |

**书库（左侧栏）**：

- 一行 = 一个工作区。工作区就是书库的一行：**没有另建的"书单"**，你删掉目录、换机器，这里显示的就是真实状态。
- 每张书卡片显示：书名（注册表标题，没有就用目录名）、相对家目录的路径（`~/小说/蜀山`，鼠标悬停看完整路径）、四态徽标、卷/章数。卷章数来自**已提交的** `chapters/index.json`；还没提交过 catalog 的书显示「卷章数未知」——书库不为此扫描正文、不重建任何东西。
- 特殊标记：**目录不在了**（注册还在但目录被删/搬走，书库不会自动移除注册）、**不是书目录**（普通目录被开成工作区；书库自己不动它，初始化请在该书的会话里让 AI 调 `inkflow_project_init`）、**重复注册 N 次**（同一个目录被注册多次，只列一行）。
- **空态**：一本都没有时显示「还没有书：用上面的「新开书」创建，或选中一本已有书的目录把它导入」。
- **刷新**：打开书库时读一次，之后点「刷新」再读。**不做轮询**——每次刷新都要对每本书跑一次门禁判定，书多时那是真实开销（并发 4、单本 2 秒、整次 3 秒、最多 200 行；单本超时的行显示「读取超时」，刷新一次再看）。
- 两个按钮都可用：**「新开书」**见下，**「共享内容」**是只读浏览（见本节末尾）。不再有禁用占位。
- **读写边界**：书单本身是只读的——书库不改目录、不建索引、不修复项目、不写任何作品文件。书库唯一会写盘的时机，是你点「新开书」并在确认卡上按了「确认创建」（见下）。

**「新开书」怎么走（ADR-0010 D4）**：

1. 点「新开书」→ 选目录。没有目录选择器时，面板让你**直接粘贴目录的绝对路径**，效果一样。
2. 面板把计划列出来：**canonical 路径**（用来核对选对了没有）、**将创建**（`git init` / 补目录 / `.gitkeep` / `inkflow.json` / `.gitignore`）、**需要你处理**（例如这本书的外层仓库要你自己去 ignore 它）、以及书名（写进 `inkflow.json`，导入已有的书时保持原样）。
   这一步**什么都没写**：它只是一次只读检查。
3. 如果这个目录不在任何已打开的工作区里，面板会先问一次「这是一个全新的目录，确认要在这里初始化成一本小说吗？」——这是防止选错目录的第二道确认。
4. 点「确认创建」之后才落盘：只执行计划里列出的动作，**只补缺失、不覆盖**已有文件；`git init` 是唯一的 git 操作（不 commit、不配远端、不改你的 git 身份）。
5. 成功后卡片写：「**书已就绪。在左侧工作区「<书名>」点「新会话」开始创作**」，并给出 canonical 路径供核对。最后这一步要你自己点——插件不能替你建会话，也不会假装跳转。
6. 如果工作区没能自动注册（宿主没给注册服务），卡片会如实说明，并提示你**在左侧手动打开该目录**；书本身已经建好了，不丢。

**会出现的拒绝，以及它的意思**：

| 你看到的 | 意思 / 下一步 |
|---|---|
| 「这个路径不能当书目录」 | 盘符根、家目录本身、系统或安装目录永不允许 |
| 「这个目录经软链接/junction 指到了工作区之外」 | 选中的目录实际落在锚定工作区之外，换真实目录 |
| 「这本书已经在书库里」 | 选到了已注册的书：它不需要重新初始化；回工作台写作，或在该书会话里修 |
| 「这本书由更新版本的插件写入」 | 本版本不写更新的书，先升级插件 |
| 「目录在检查之后被改动过」 | 有人/别的会话在两步之间改了目录：重新检查一次再确认（不会写一半） |
| 「这份计划已经用过了 / 超过五分钟了」 | 一次计划只能确认一次：重新选目录或重新检查 |

**工作台（会话页签）**：

面板**只读地判定这本书的状态**（四态门禁），`usable` 时右栏是可直接写作的编辑器；非 `usable` 时一切写入仍然只能由工具完成：

| 面板状态 | 你看到什么 | 下一步 |
|---|---|---|
| **可用**（`usable`） | 顶部：项目标题、四态徽章、项目根（相对会话目录，通常就是 `./`）；左：章节树（卷 → 章，可「新建章」）；右：标题 / 状态 / 正文编辑器 | 直接写：停止输入 1.5 秒自动保存，`Ctrl/Cmd+S` 立刻保存，`Ctrl/Cmd+Z` 撤销；文件在插件外被改过时提示冲突，默认**不**覆盖（重载或明确覆盖由你选） |
| **待初始化**（`needs-setup`） | 缺什么（`missing[]`）+ 初始化向导会做什么（`actions[]`）+「打开初始化向导」按钮 | 点按钮看只读计划；确认后让 AI 调 `inkflow_project_init`（`confirm: true`） |
| **待修复**（`needs-repair`） | 同上，清单是缺的目录/`.gitkeep`/`inkflow.json` 等 | 同上：先看计划，再确认补齐（只补缺的，不覆盖已有文件） |
| **需升级插件**（`needs-newer-plugin`） | 只读提示：这本书由更新版本的插件写入 | 先升级插件，这个版本不写入 |
| **没有会话身份**（`NO_SESSION_CONTEXT`） | 明确空态文案，不是报错 | 在小说目录的会话里打开这个页签 |

- 页签可用性：**章节**、**设定库**（八类设定树 + 条目编辑 + 问题面板）、**伏笔**（只读看板：本期到期 / 超期 / 未回收 / 按角色）、**回收站**（删了什么、还能不能恢复）、**体检**（五类问题一次列全 + 导出报告）已可用；**大纲**仍是禁用态并标注「0.2.0 起」——摆一个点了没反应的按钮比禁用更糟。
- 伏笔看板**只读**：它列的是 Host 算出来的状态（`dueBy` 已越过当前章/卷且未回收即「超期」），文件里的 `status` 只是其中一列。要改伏笔（埋 / 推进 / 回收）让 AI 调 `inkflow_foreshadow_upsert`——状态机与确认门禁都在工具上，面板不做表单。
- 工作台与书库都不写盘、不建索引、不修复项目：它们只投影 Host 的判定结果，写入一律是「用户确认后的工具调用」。
- 面板看不到内容时，项目状态也可以直接问 AI：`inkflow_project_status`（判定）与 `inkflow_project_plan`（只读计划）。

**共享内容（只读）**：点「共享内容」进入共享库浏览页。共享库是**插件级**目录（`<插件数据目录>/shared/`，缺省 `~/.dsh/inkflow/shared/`），不属于任何一本书，里面按四类放条目：世界观 / 设定（`world/`）、资料（`library/`）、写作片段（`snippets/`）、系列（`series/`）。页面按这四类分组，每条显示条目名、相对路径和标签。

- **顶部会写明这份清单是怎么来的**：`shared/index.json`（派生清单）与目录一致时直接用它；清单缺失、读不懂，或与目录对不上，就在内存里重扫一遍目录重算，并标注「数据来源：内存扫描，未写回 index.json」。重扫**不会**改清单文件。
- **共享库还没建时不报错**：页面显示「共享库尚未创建（0.4.0 支持）」，并且不会替你建目录、不写任何文件。想去手工准备也可以，四类目录与 `index.json` 的字段见规格文档。
- **这一页只读**：把某条**复制 / 引用**到某本书还不在这里（0.4.0 提供，#40）。所以页面上只有「刷新」和「返回书单」两个动作；**没有轮询**——打开时读一次，之后点「刷新」再读一次。
- 这一版页面只按类别分组展示，**没有搜索框**；共享内容通道本身支持 `kind` 与 `q` 两个过滤参数（`/inkflow/internal/hub/shared?kind=world&q=白鹤`），适合脚本核对条目。

### 5.2 对 AI 说人话就行

插件提供三十一个工具（15 个内置 + 16 个域工具），DSH 里的 AI 会在需要时自己调用。写作用的那几个，你直接说人话就行：

**项目与索引**

| 工具 | 作用 | 你可以这样说 |
|---|---|---|
| `inkflow_project_status` | 检查当前目录的项目状态（可用 / 待初始化 / 待修复 / 需升级插件）、缺什么、索引状态 | 「看看这个目录能不能写小说」 |
| `inkflow_project_plan` | **只读**：列出"若初始化/修复，会创建哪些目录与文件"，不写任何东西 | 「先给我看看你打算建什么」 |
| `inkflow_project_init` | 执行上面那份清单（建目录 + `.gitkeep` + `inkflow.json` + `.gitignore` + 必要时 `git init`）；**只补缺的，不覆盖已有文件**；必须带确认 | 「就按这个清单建」/「把缺的补齐」 |
| `inkflow_index_rebuild` | 从文件重建索引并检查一致性 | 「重建一下索引」 |
| `inkflow_project_audit` | 一致性体检：结构 / 账本 / 伏笔 / 时间线 / catalog 五类一次列全，每条带定位与修法；`export: true` 再导出 Markdown 到 `.inkflow/audit/` | 「体检一下这本书」/「导一份体检报告」 |
| `inkflow_project_repair` | 三段式修复：`detect` 只列问题、`preview` 只给动作（零写盘）、`fix` 才写（需确认）；只补必填键 / 按证据字段推导伏笔 `status` / 重挂 parent / 删重复关系 / 重建 catalog | 「看看能自动修哪些」/「把能修的修掉」 |
| `inkflow_project_migrate` | 老六目录书升到九目录：`plan` 只读、`apply` 需确认、`rollback` 从 `.inkflow/backup/` 回滚 | 「这本书是老结构，迁一下」/「刚才那次迁移撤回」 |

**卷与章**

| 工具 | 作用 | 你可以这样说 |
|---|---|---|
| `inkflow_chapter_list` | 按阅读顺序列出章节 | 「列一下现在有哪些章」 |
| `inkflow_chapter_search` | 在章节正文里找关键词，返回命中的章与前后各 40 字的片段（1–2 个字也能搜） | 「哪一章写过云海翻涌」/「搜一下『宝剑』」 |
| `inkflow_volume_create` | 建卷：分配 `vol-NN`、建 `chapters/vol-NN-<slug>/` 并刷新卷章清单 | 「开一个第一卷」 |
| `inkflow_volume_rename` | 改卷名：目录与清单一起改，**章的归属和章 id 不变** | 「把第一卷改名叫入山卷」 |
| `inkflow_chapter_create` | 建章：分配 uuid `id` 和章号，写 frontmatter 与空正文 | 「加一章，标题叫第一章 入山」 |
| `inkflow_chapter_write` | 改标题 / 正文 / 状态；只改你指定的字段，改标题会同时改文件名 | 「把这一章改成《夜行》，状态标成 revised」 |
| `inkflow_chapter_move` | 移卷或移出卷（`volume` 跟着改，章 id 不变） | 「把第三章挪到第二卷」/「把这篇外传移出卷」 |
| `inkflow_chapter_delete` | 删章：正文先进**回收站**（`.inkflow/trash/`），可以原样恢复；再点一次才是彻底删除 | 「删掉那一章」/「刚才删错了，恢复回来」 |

**设定库（角色 / 世界观 / 大纲 / 关系 / 时间线 / 伏笔 / 账本）**

| 工具 | 作用 | 你可以这样说 |
|---|---|---|
| `inkflow_character_list` | 列角色卡（名字 / 别名 / 分组 / 角色 / 视角 / 出场章 / 语言基因 / 按章状态），可按分组或名字片段筛；带上章号就问「第 30 章时他是什么状态」 | 「列一下门派里有哪些人」/「第 30 章时清音是什么身份」 |
| `inkflow_character_upsert` | 建或改角色卡：同名再写就是改这张卡；名字与别名项目内必须唯一（撞名直接拒），必须带确认 | 「给清音建张人物卡，别名青音，属白鹤门」/「把她第 30 章的状态改成代掌门」 |
| `inkflow_world_tree` | 展开世界观树（按分类分组），可只取一个分类 | 「世界观里门派下面都有什么」 |
| `inkflow_world_upsert` | 建或改世界观条目：父节点必须存在、非根条目必须带分类，必须带确认 | 「加一个门派叫青萍宗，挂在白鹤门下面」 |
| `inkflow_outline_tree` | 三层大纲树（整体 → 卷 → 章），带情节点 | 「把大纲列出来」 |
| `inkflow_outline_upsert` | 建或改大纲节点：卷只能挂整体、最多三层，必须带确认 | 「给卷一加一条情节点」 |
| `inkflow_outline_move` | 移动大纲节点改父级（卷中卷、章挂章会被拒） | 「把这条情节挪到第二卷」 |
| `inkflow_relation_list` | 查一个实体两个方向的关系边 | 「清音和白云观是什么关系」 |
| `inkflow_relation_upsert` | 建或改关系边：两端必须存在、禁自环、同源同目标同类型不许重复 | 「记一条：清音与白云观是旧识」 |
| `inkflow_timeline_list` | 时间线双轴（世界时间 / 叙事顺序），可只看某一章、也可列待确认事件 | 「这本书里的大事按时间排一下」/「哪些事件还没定时间」 |
| `inkflow_timeline_upsert` | 建或改时间线事件；`confirmed` 必须带世界时间，同槽位不许两个时间 | 「记一笔：开元十三年冬，破庙相遇」 |
| `inkflow_foreshadow_list` | 列伏笔（按状态 / 只看超期 / 按关联实体筛），超期是**算出来的**（`dueBy` 已越过当前章/卷且未回收） | 「哪些伏笔该收了」/「有没有超期没回收的」 |
| `inkflow_foreshadow_upsert` | 建或改伏笔并推进状态：`planted → advanced → resolved`，`resolved` 是终态；非法跳变直接拒 | 「埋个伏笔：断剑，打算在第 20 章收」/「断剑这章推进一下」 |
| `inkflow_facts_append` | 往账本追加一条事实（截至某章、某属性等于某值），写前先过区间冲突校验 | 「记下来：到第 12 章清音的境界是筑基后期」 |
| `inkflow_facts_list` | 列账本事实与冲突（可按主体 / 属性筛） | 「账本里有冲突吗」 |
| `inkflow_facts_snapshot` | 「截至第 N 章」的事实快照，结果可复现 | 「写第 15 章时，他手上有什么、是什么境界」 |

向导的两段式是刻意设计的：先看清单（`plan`），你点头之后才落盘（`init` + 确认）。修复老项目时它只补缺失项——已有的正文、设定、`inkflow.json` 一个字节都不会动；唯一例外是**坏掉的** `inkflow.json`：它会先把原文（超长会截断并标注）给你看，你确认后才重建。

### 5.3 自己改文件后

用 VSCode/记事本直接改 `.md` 文件是**允许且推荐**的。改完让 AI「重建索引」，或手动调用 `inkflow_index_rebuild`。

### 5.4 写作模式与五个写作技能

装好插件后，在**小说项目目录**里开会话，AI 的技能目录里会自带五个写作工艺技能：

| 技能 | 管什么 |
|---|---|
| `inkflow-architect` | 架构：把设定与大纲折成**本章任务书**（目标 / 冲突 / 信息增量 / 伏笔动作 / 禁区） |
| `inkflow-writer` | 起草：按任务书写正文，管视角、场景、对话、节奏、章末钩子、去 AI 味 |
| `inkflow-auditor` | 审校：设定 / 时间线 / 人物 / 伏笔四维**只读**审计，逐条给正文原句与严重级 |
| `inkflow-reviser` | 修订：按审计清单定向改写，只动被点名的位置，不重写全章 |
| `inkflow-polisher` | 润色：句子级去 AI 味、去翻译腔、修重复与标点，**不改情节** |

这些技能**只在作品目录里出现**：会话工作目录不在任何 InkFlow 项目里时，技能目录里不会有它们，写代码/聊天类的会话不受影响。

**写作模式（agent preset）**：会话的模式选择里会多一项 **InkFlow 写作**（`inkflow-writing`）。它的差别只有两件事：

- 人设按五阶段流水线组织，并点名这五个技能；
- 工具只给读文件 / 文件搜索 / 待办 / 提问 / 联网这些日常工具，外加 `inkflow_*`。**不给 shell、不给子智能体、不给工作流**——作者会话不该顺手去改仓库。

写小说用这个模式，写代码用默认模式。

**怎么用**（照旧说人话，不用记技能名）：

- 「写下一章」→ 先 `inkflow-architect` 出任务书，再 `inkflow-writer` 成文，最后 `inkflow-auditor` 审一遍；
- 「按审校意见改」→ `inkflow-reviser`；「这段读着像 AI 写的，润一下」→ `inkflow-polisher`；
- 想直接点名，输入框里打 `/inkflow-writer` 即可。

**想改工艺**：技能文件在插件包内 `skills/<技能名>/SKILL.md`，正文就是给 AI 的指令（frontmatter 里的 `name` 必须与目录名一致，改名要同时改两处）。技能按作品目录生效，所以同一套工艺对所有书一致。

### 5.5 删了能找回：回收站

删章不再是一去不回：正文会先进 `<书>/.inkflow/trash/`（保持原相对路径），旁边有一份清单记着删除时间、字节数与 `sha256`。

- **恢复**：回收站页签里点「恢复」，文件回到原路径，**字节完全一致**（BOM、CRLF 都原样）。原路径已经被别的文件占了就**拒绝**，不会覆盖你新写的东西。
- **彻底删除**：要**点两次**（第一次只是把那条点亮），后端还要 `confirm: true`，两个条件缺一不可。
- **同一个路径只占一个槽位**：想再删一次同名文件，得先把回收站里那条恢复或彻底删掉——否则第二次删除会把第一条的副本覆盖掉，那条就再也找不回来了（插件现在直接拒绝这种删除）。
- **`.inkflow/` 不进 git**：第一次写入时插件会往 `.gitignore` 追加一行 `.inkflow/`，所以 `git status` 不会被回收站弄脏；也正因如此，**回收站不随 git 同步**——跨机器靠的是 git 提交历史，回收站只解决「还没提交时的误删」。
- 删掉 `index/` 重建索引**不影响**回收站（它不在 `index/` 下面，这是刻意的：`index/` 缺失会被静默重建）。

### 5.6 伏笔：埋了就别忘了收

- 四个状态：`planted`（已埋）→ `advanced`（已推进）→ `resolved`（已回收），另有 `overdue`（超期）。**`resolved` 是终态**，其它非法跳变（比如回退到 `planted`）会被直接拒。
- **超期是算出来的，不是存下来的**：`dueBy`（期望回收的章或卷）已经越过「当前章」而状态还没到 `resolved`，看板就把它标成超期。所以你把某一章往回改、或者把 `dueBy` 往后挪，超期会自动跟着变——文件里不需要（也不该）手写 `status: overdue`。
- **看板分四段，按「现在该动手」排序**：本期到期 → 超期 → 未回收 → 按角色。**本期到期**是 `dueBy` 正好等于正在写的那一章（这是回收它的最后机会，还没算超期）；**未回收**是全部未回收条目（含上面两段的）；**按角色**列关联的条目。某一段没有条目时**整段不显示**——不会出现「本期到期（0）」，零的数量看顶部那行摘要（`超期 N · 本期到期 N · 未回收 N / 共 N`）就够。
- **写作时会有提示**：在会话里写某一章时，写作上下文会多一段「伏笔提示」，列出**建议本章回收**的条目（超期的 + `dueBy` 正好是本章的）。这段读的是文件，不是索引——手改了文件还没重建索引也不会漏。
- 看板只读；改伏笔让 AI 调 `inkflow_foreshadow_upsert`（状态机与确认都在工具上）。

### 5.7 改设定：先看影响面，改名只写一次

改一个设定条目（世界观 / 角色 / 大纲 / 关系 / 时间线）之前，设定库编辑器的「影响面」会先列清楚：**哪些章提到过它**（带出现次数）、哪些关系/时间线/账本/伏笔引用了它，以及总共多少处。

- **只生成清单不执行 = 零写入**：关掉对话框就行，项目文件一个字节都不变。
- **改名的语义是「id 钉住」**：文件换名字，旧 id 写进新文件的 `id` 字段，**五处引用一个都不改**。所以改完名字，关系、时间线、账本、伏笔、正文提及全都还连着。
- 只改显示名（不改文件名）**不会**写 `id`；路径没变就没有「改过名」这回事。
- **两个保存不会同屏当按钮**：内容有未保存的改动时，「改名与影响面」整块收成一行灰字（先保存或放弃，再改名）；点过「查看影响面」且内容没有未保存改动时，「保存」退成一行灰字，只有「确认改名」是按钮。没点过「查看影响面」就看不到「确认改名」——那行字会告诉你要先点它。
- 拒绝的情况：目标文件名已存在、文件名以点开头（点开头的条目所有扫描都会跳过，写进去就只剩 git 能救）、`con`/`nul` 这类保留名、显示名带换行。账本（`facts/`）不参与改名——文件名就是它的主体。

### 5.8 体检与一键修复

- **体检**（`inkflow_project_audit` / 体检页签）：结构不变量、事实账本冲突、伏笔超期、时间线矛盾、catalog 偏差五类一次列全，每条带定位（`kind:id` / `chapter:<id>` / `path#L<n>`）与一句修法。同一份没改过的书跑两次，报告正文**逐字相同**（可以进 git 对比）。
- **导出**：报告可以写成 Markdown 落到 `<书>/.inkflow/audit/`——它是派生物，删了随时能重算，所以不进 git。
- **一键修复**（`inkflow_project_repair`）是三段式：`detect` 只列问题、`preview` 只给动作（**零写盘**）、`fix` 才写（要确认）。它**只补不改**：补 frontmatter 必填键、按证据字段推导伏笔的 `status`（与 `resolved` / `resolvedChapter` / `advancedAt` 矛盾时按确定规则改那**一行**，两字段互相矛盾时留给作者）、重挂错误的 `parent`、删重复关系、重建 catalog 投影；**修不掉的一律不进自动修复**（比如悬空引用、坏账本行），报告里会说明为什么。修完会**重跑同一套检查**证明问题消失。

### 5.9 老书升级：六目录 → 九目录

早期版本的书只有 `chapters/ characters/ world/ outlines/ library/ index/`。新的九内容目录契约多出 `foreshadowing/ timeline/ relations/ facts/`，**内容文件不需要搬家**，缺的只是目录与 `.gitkeep`。

- `inkflow_project_migrate` 的 `plan` 是**只读**的，会逐项列出要做什么；`apply` 需要确认。
- **只补不改**：已有的 `.md` 一个字节都不动（`.gitignore` 只追加缺的行，`inkflow.json` 只升 `schemaVersion`）。
- **执行前先开备份包**：受影响文件快照进 `<书>/.inkflow/backup/<时间戳>/`；中途失败**不会自动回滚**（改的是已存在的文件，撤销必须能跨进程重放），你可以用 `rollback` 从那个包里退回去——回滚会先核对「改动后」的摘要，你在迁移之后又编辑过的文件会被保护并报冲突。


### 5.10 事实账本的两个约定

- **文件名不等于主体**：`facts/叶知秋.md` 的 `subject` 可以是 `char-yezhiqiu`（老书都是这种写法，文件名只是位置）。追加事实时按 `subject` 找文件，找不到同名文件也不会另建第二份。
- **一条事实一个正文列表项**（`- attribute: 境界 | value: 筑基后期 | since: <章 id>`）。老文件把**一条事实写在 frontmatter** 里（`attribute` / `value` / `source`），插件仍然读得出来（只读兼容），但**不要再新增**这种写法；正文里的散文与表格不会被当成事实，也不会再报「坏行」。

## 7. 索引是什么

- 位置：`<书名>/index/inkflow.db`（SQLite，WAL）。
- 内容：章节、角色、世界观、大纲的**摘要** + 全文检索表（中文 ≥3 字可搜，2 字走退化的精确匹配）。
- 特性：**可随时删除**。删除后下次打开/调用工具会自动重建，耗时与文件量成正比（几千章量级预计数秒）。
- 索引**不进 git**（`.gitignore` 里已排除），所以不会污染你的提交历史。

## 8. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板显示「没有会话身份」（`NO_SESSION_CONTEXT`） | 面板在会话的「对话 / 轨迹」栏里才有会话身份；从没有会话的页面打开、或会话还没绑定工作区时，Host 无法判断该显示哪本书 | 在小说目录的会话里切到 InkFlow 页签；同时可调 `inkflow_project_status` 看项目状态 |
| 工具报 `NOT_AN_INKFLOW_PROJECT`（`needs-setup`） | 这里还不是项目：缺 git / 缺目录 / 缺 `inkflow.json` | 看返回的 `missing` 与 `actions`；确认后让 AI 走 `inkflow_project_plan` → `inkflow_project_init`（`confirm: true`） |
| 工具报 `PROJECT_NEEDS_REPAIR`（`needs-repair`） | 书已经存在，但缺目录/缺 `.gitkeep`/`inkflow.json` 坏了 | 先看 `actions`（只补缺失项，不覆盖已有文件）；坏 meta 会先回原文再重建 |
| 工具报 `PROJECT_NEEDS_NEWER_PLUGIN` | `inkflow.json` 的 `schemaVersion` 比你装的插件新 | **升级插件**；不要试图修复或重建——旧版本写入会破坏新版本写下的数据 |
| 工具报 `META_TITLE_REQUIRED` | 需要写 `inkflow.json` 但没告知书名 | 告诉 AI 书名后重试（插件不编造标题） |
| 工具报 `GIT_INIT_FAILED` | 机器上没有可用的 git | 装好 git 后重试；或自己在书目录 `git init`，再走修复向导 |
| 工具报 `PATH_OUT_OF_SCOPE` / `PATH_FORBIDDEN` | 传的路径不在当前会话工作目录里（或是盘符根/家目录/安装目录） | 在会话工作目录内建项目，或先把会话切到书的目录 |
| 工具报 `INIT_REQUIRES_CONFIRMATION` | 向导还没拿到你的确认 | 看返回的「将创建/将修复」清单，确认无误后让 AI 带 `confirm: true` 再跑一次 |
| 会话的「对话 / 轨迹」栏里没有 InkFlow 页签 | 插件未安装/未激活，或改了代码没重启（HMR 不热替换已加载的插件） | 检查插件列表；重启 DSH |
| 装了插件但工具列表里没有 `inkflow_*` | 还是旧版本代码在跑 | 重启 DSH |
| 技能目录里没有 `inkflow-*` 五个写作技能 | 会话工作目录不在 InkFlow 项目里（技能按目录门禁），或宿主没有 skills 服务 | 把会话切到书的目录；重启后在启动日志里看有没有 `skills service missing` |
| 模式选择里没有「InkFlow 写作」 | 宿主没有 `agentPresets` 服务（或该宿主不支持 preset） | 技能与 `inkflow_*` 工具不依赖 preset，写作照常可用；重启升级后再看 |
| 改了章文件，面板还是旧的 | 索引未重建 | 触发 `inkflow_index_rebuild` 或重启会话 |
| 中文两字词搜不到 | trigram 分词限制 | 用 3 字以上关键词，或直接全文搜文件 |
| 文档乱码 / 项目识别失败 | 文件被写入了 UTF-8 BOM | 用「UTF-8 无 BOM」重新保存；插件读取时会容忍 BOM，但建议统一 |
| 书名/正文乱码（如 `浜哄湪铚€灞憋紝鏄帉闂?`） | 文件根本不是 UTF-8：PowerShell 5 的 `Set-Content` / `echo` 默认 ANSI，在中文 Windows 上写出的是 GBK；插件自己的写入路径不会这样 | 用「UTF-8 无 BOM」重写这个文件，书名可以让 AI 用工具重新写一次。插件会发现并提示（`inkflow_project_status` 的 `titleSuspicious`、`inkflow_project_init` 的 `META_ENCODING_SUSPECT`、面板标题旁的 ⚠），但**不会自动改你的文件** |
| `git clone` 后插件说缺目录 | 空目录被 git 丢了（`.gitkeep` 被删） | 删掉过 `.gitkeep` 就会这样：让 AI 走修复向导补回来，或手动补空文件 |
| 面板顶部出现「插件代码已更新…重启 DSH」警告条 | 运行中的插件是**旧代际**：`lib/` 在这次 DSH 启动之后又被构建过，而 DSH 只在启动时加载一次插件（HMR 不热替换），旧代码里也没有新路由与新面板 | 先 `pnpm.cmd run build`，然后**完全退出 DSH 再启动**；面板里的「重新检测」不会生效——它重跑的仍是同一份旧代码 |
| 怎么知道插件是不是旧代码 | 面板页头的 `build xxxx` 就是这块代码的构建标识（`<git 短 sha>@<构建时间>`）；顶部警告条出现，说明磁盘上的 `lib/` 比当前进程新 | 有警告条 → 按上一行重启；没有警告条 → 你跑的就是磁盘上那份代码 |
| 更新了插件 / 改了代码，行为却没变 | 同上：插件代码在进程启动时加载一次，装新版本或重新构建都不会替换已经加载的代码 | 完全退出 DSH 后再启动；启动日志里的 `build <标识> loaded at <时间>` 可与面板上的标识核对 |

## 9. FAQ

**Q：我的书会被上传吗？**
不会。第一阶段完全本地：没有账号、没有服务端、没有同步。只有你主动调用模型生成内容时，相关上下文才会发送给你自己配置的模型服务。

**Q：能多本书吗？**
能，但**一个会话工作区只管一本书**：一本书 = 一个目录 = 一个 git 仓库；在不同书的目录里分别开会话即可，插件不会跨目录串数据。

**Q：怎么备份？**
`git push` 到你的私有远端即可。这也是推荐做法：每完成一章提交一次。

**Q：可以不用 git 吗？**
不可以。git 是本设计的版本历史与回滚面，也是插件识别项目的条件之一。

**Q：卸载插件后书还在吗？**
在。作品是普通文件 + 你自己的 git 仓库，与插件无关。

**Q：能自定义目录名吗？**
不能。目录名是项目契约的一部分（见 `.agents/specs/conventions.md`），改名会导致插件不认这个项目。
